# Qlyra 2.5.1

修复 QQ 回复协议泄漏、日常语音复读与媒体失败提示进入聊天的问题。

- 日常聊天中的文字与语音各说一个意思。宿主识别逐字、标点差异及高度相似的重复；自动语音重复时保留文字，明确要求语音时把相同内容移到语音。明确要求朗读及 `/语音 原文` 保持照读。
- JSON 围栏、重复编码与缺少结尾容器在聊天拆句前解码，损坏协议不会作为正文发出。
- 图片发送发生超时时，按发送前历史、自己发送者身份、时间及图片 MD5 查询回执；只有唯一的新匹配才确认成功，不因超时重复发图。无法确认时仍记为未完成。
- 媒体发送、语音合成及可选语气分析的技术错误仅进入本机日志。独立语音合成失败时保留其正文为文字，不附加接口错误、NapCat 排查提示或密钥信息。
- 当前语音模型及唱歌能力传给聊天模型。小米官方规定预置 `mimo-v2.5-tts` 支持 `(唱歌)` 标签，声音设计和声音复刻模型不支持唱歌；不自动替换用户的复刻音色。

聊天模型可继续使用已提供的 ChatGPT / Codex 登录后端。选择文字模型不会替换 MiMo TTS，也不会把 Plus 登录变成声音生成 API。

包含 Windows 安装包、便携包及 NapCat 插件包；以同目录 SHA256SUMS.txt 为准。单元测试和模拟传输不代替真实 QQ 图片显示、音频播放与歌声质量验收。
