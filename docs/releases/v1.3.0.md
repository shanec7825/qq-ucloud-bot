# 1.3.0 — 直接使用 NapCat 原生界面

此版本采用 NapCat 自己的插件配置面板，替代 1.2.0 的自绘工作台。推送 main 后由仓库现有 GitHub Actions 构建发布。

## 界面行为

- 插件配置直接由 NapCat 原生输入框、开关、下拉选择、说明文本和保存按钮渲染，不嵌入 iframe，不加载自绘管理页或覆盖 NapCat 样式。
- 机器人、群组、可复用方案、长期记忆、历史摘要、最近上下文和消息事项在原生配置页中选择并操作。
- 桌面程序在服务可用时直接进入 NapCat；首次准备或服务停止时提供简化恢复入口。
- 模型、群权限、记忆作用范围和消息整理沿用 1.2.0 的后端。界面预览和切换不调用模型，也不立即写入配置；通过 NapCat 的“保存”明确提交。

## 原生能力边界

以本地 NapCat 4.18.38 实际渲染器为准，支持 string、number、boolean、select、multi-select 和只读 text。本版本的 text 是只读文本，并非多行编辑框；原生面板也没有密码框。长文本通过原生输入与只读预览管理。已保存密钥不回显，替换值仅在本次输入中使用，留空保留原值。

原生配置模式参考 [NapCat 官方文档](https://napneko.github.io/develop/plugin/start-webui)，并以本机运行代码核对保存钩子、响应式更新和默认值行为。未修改 NapCat 前端或全局安全机制。

## 升级

安装 1.3.0 后继续选择原项目。独立 NapCat 使用同版本插件包替换对应模块后重载。升级前备份工作区 `data/` 和 `.env`；已有群、方案、记忆与通知报告保留。需要更换原生配置模块时应先保存当前编辑。

## 验证

使用发行版 Node 24.22.0 通过 107 项自动化测试。Edge 直接加载本机 NapCat 原版静态前端，在隔离接口下验证五个模块、四次原生保存、群方案绑定、记录切换、过期表单拒绝、安全记忆与来源预览、390px 深色布局，模型请求和 QQ 发送均为零。桌面宿主使用实际 .NET Framework 编译器编译通过，保存重试与桌面导航竞态均已审查修复。

详细运行方法见 [原生界面验证](../NAPCAT-NATIVE-UI.md)，本地发行目录另有包内容审核文件。原生 UI 验收使用本机 NapCat 原版静态前端与模拟接口，不把测试状态作为真实 QQ 登录、模型或学校服务的联调证据。
