# 自然聊天、按语境选语音与动漫表情

日期：2026-10-23。实现基于现有 NapCat / OneBot 连接。

## 本次行为

日常聊天优先一次生成 2–4 条有完整意思的短消息，简短回应可只发一条，最多八条。模型先决定语义分组；未分组的短口语文本再按句末标点兜底拆分。代码、网址、公式、列表和需要整体阅读的解释保持完整。不在逗号处碎切，不为凑数添加消息。

首条立即发送；后续气泡按长度间隔约 0.4–1.2 秒。如果前面的语音合成已经产生足够等待，就不额外延迟。群内只在第一条成功消息引用、@ 用户。发送失败或会话权限变化时停止剩余发送，整轮保持同一会话队列。

语音页的「按语境决定语音」沿用原来的 `speech.autoReply` 开关。开启时，聊天模型在同一次请求里选择是否需要语音，默认可以完全不发。安慰、问候、情绪表达和读音示范适合短语音；代码、网址、地址、长清单、详细步骤优先文字。每轮自动语音最多一条、最多 180 字，同时受配置字数上限约束。多出来的独立语音内容会转为文字，防止丢失信息。

用户说「只发文字」「别发语音」时本轮禁止语音；说「用语音回答」「发条语音」时本轮明确要求语音。关闭自动选择后，明确要求与 `/语音 原文` 仍可使用。文字 `text` 与实际说出的 `speech.text` 可互相补充；`speech.style` 只调表达，保留预置、文字设计或参考音频确定的声音身份。

## 动漫素材

固定目录收录 374 个表情、20 套作品与主题，包含小埋、摇曳露营、咒术回战、工作细胞、柯南、蜡笔小新、铃芽之旅、公主连结、约会大作战、初音未来、pop 子与 pipi 美、犬王。一个作品可有多套主题。

目录保留素材原名、原图地址、公开索引来源、角色别名和情绪标签。图库支持作品、情绪和名称搜索，每批展示 24 个；可启用筛选结果，查看进度，停止后续下载。启用后图片存入 `data/outgoing-media/`，QQ 发送使用本地已校验字节。原有账号和会话素材权限继续生效；推荐图库启用的素材按已有共享规则供所有登录 QQ 使用。

素材库数量上限由 200 调整为 1000，总容量仍为 200MB、单文件仍为 8MB。聊天每次只取得至多 40 项相关素材的名称、ID 和标签，按问题、作品、情绪排序并保留作品多样性。不会只看最早入库的 80 个，也不会把整库图片地址或字节放入模型上下文。

全量目录见 `src/anime-media-catalog.json`，实物完整性报告见 `data/anime-media-import.json`。再次运行 `node scripts/import-anime-media.mjs --enable` 只补缺项；`--verify` 只核验本地文件。

## 项目调研与取舍

| 来源 | 核对到的实现 | 本项目采用的方式 |
| --- | --- | --- |
| [AstrBot 分段配置](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/config/default.py)与[结果装饰管道](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/pipeline/result_decorate/stage.py) | 支持按标点拆分、分段等待、语音触发概率；非文本消息不走文字拆句 | 保留模型分组，短口语才兜底拆句；语音由语境选择，另加宿主数量与内容约束 |
| [MaiBot 语义断句器](https://github.com/Mai-with-u/MaiBot/blob/main/src/chat/utils/llm_sentence_splitter.py) | 用模型按自然语义断句，并检查结果与原文一致；代码、公式和整体阅读文段可不拆 | 在原来的一次回答请求中直接生成气泡；本地兜底只选择原文切点，避免额外模型请求和延迟 |
| [QQ 官方消息收发概述](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)与[接入说明](https://bot.q.qq.com/wiki/develop/api-v2/) | 官方机器人支持单聊、群聊、频道；富媒体先上传后发送；官方接入使用 AppID / AppSecret | 当前保留 NapCat 连接；官方接入作为独立适配器方向，不能直接替换个人 QQ 登录和现有历史读取 |

QQ 官方文档在本次核对时规定：被动回复单聊有效期 60 分钟、每条可回复四次；群聊有效期五分钟、每条可回复五次。`msg_id + msg_seq` 用于回复去重。这些是官方通道规则，不能套用为 NapCat 的能力证明。若以后接入官方通道，应按其限制合并气泡、计入图片和语音发送次数；不能直接照搬八条计划。

动漫元数据来自 [BiliEmoji 公开索引](https://github.com/lrhtony/BiliEmoji/tree/224dd0d5e63f1459df0f6b53873e91275a3a1296)及 B 站公开表情详情接口，图片权利归原作者；目录可访问性不代表商业再分发授权。本次独立实现消息策略，没有复制上述项目源代码。

## 核验与证据边界

- `test/chat-presentation.test.mjs` 覆盖语音选择、显式偏好、自动语音限制、信息保留、拆句完整性、媒体只发送一次、间隔中撤权和整库素材检索。
- `test/anime-media.test.mjs` 覆盖真实目录结构、来源约束、重复导入合并、元数据保留和异常响应拒绝。
- `test/atomic-file.test.mjs` 覆盖 Windows 短暂文件占用重试、重试上限和其他错误传播。替换失败时不删除旧文件。
- `scripts/check-extension-ui.mjs` 的隔离浏览器用例覆盖图库分页、作品/情绪/名称筛选、批量启用及窄屏布局；不会发送 QQ 消息或调用模型。
- 素材实物校验涵盖 374 个文件的类型、尺寸和 SHA-256。单元、浏览器、文件校验不等于真实 QQ 送达或 MiMo 声音效果；这些需要登录后的实际对话确认。

源码与素材完成后交由已获用户授权的「实现 Qlyra 音频克隆与图标」聊天统一构建、合并素材和部署，避免同时覆盖现用目录。
