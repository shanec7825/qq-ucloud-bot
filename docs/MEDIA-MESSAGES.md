# 图片、表情包与 QQ 原生语音

NapCat「机器人」扩展工作台新增 **图片与表情包** 和 **语音** 两页。群聊仍需在允许回复的群内 @ 机器人；静默监测群保持静默。

## 一次回复发送多条消息

模型可按交流节奏输出 1–4 条消息，每条包含文字和可选的图片、表情包或语音。每条正文最多 1500 字，整轮最多两张素材；不为凑数拆分代码块和连贯段落。模型一次生成完整分条计划，宿主校验后顺序发送。

每条文字之后发送该条的图片和原生语音，再进入下一条。群内只在首个成功发送的消息添加引用和 @。当前会话的整轮消息发完后才处理下一条请求，其他会话可继续各自处理。

发送失败或权限变化时停止后续投递，不自动重放可能已经发出的消息；记忆保留已投递内容与未完成状态。语音按每条正文和表达指导分别合成，同一轮最多四条，共用一次频控名额；语音生成失败保留对应文字，不反复请求失败服务。

## 图片与表情包

- 页面上传 PNG、JPEG、GIF、WebP，单个最大 8MB，最多 200 个、总计 200MB。原文件保存到 `data/outgoing-media/`，GIF 保留原始字节。
- 上传时选择 QQ 账号、图片/表情包和使用范围：指定群、指定私聊或整个账号。整个账号的素材会在该账号的各会话中提供给机器人选择，请按实际共享意图设置。
- 在 QQ 附图或引用当前会话图片后发送 `/收藏图片 名称`、`/收藏表情包 名称`。普通用户也可收藏，但只保存到当前会话。引用其他会话的消息会被拒绝。
- `/图片`、`/表情包` 查看当前可用素材，`/图片 名称`、`/表情包 名称` 发送。支持列表编号或完整素材 ID；重名时使用编号或 ID。
- 模型会获得当前会话可用素材的名称与 ID，可以按话题选择最多两项配图。宿主校验 ID 和会话权限后发送。模型不能指定本机文件路径或任意 URL。
- 页面可预览、删除；收藏内容在重启后保留。素材按账号与会话隔离；同一会话更换人格不会清除其素材。

## 小米 MiMo / Token Plan 语音

1. 在「语音」页选择服务地址，输入与之匹配的 Key：Token Plan 中国、新加坡、欧洲集群，或普通 API `https://api.xiaomimimo.com/v1`。使用自己的套餐页面显示的对应地区地址与授权。
2. 开启语音、选择音色和语气，保存后生成试听。Key 加密保存在现有密钥库中，页面留空保留。
3. 发送 `/语音 你好` 或 `/朗读 Hello` 朗读原文；发送 `用语音回答：你的问题` 合成模型回复。可开启「自动附带语音」，为普通聊天回复附带语音。

默认模型为 `mimo-v2.5-tts`，默认中文音色「冰糖」，另有茉莉、苏打、白桦和 Mia、Chloe、Milo、Dean 等音色。接口为所选根地址的 `/chat/completions`，请求非流式 WAV。

### 每条回复的自动表达

默认开启「按内容自动调整表达」。普通语音回复在同一次对话模型请求中生成最终正文和单独的 `speech.style`，根据回复语义、人格与已授权上下文安排语调、情绪、语速、停顿、重音、气息及声音质感。无需另开一个 Agent 或为普通回复增加一次分析请求。

固定音色或音色描述保持为设置中的值；管理员的「固定语气与语速要求」优先。本条指导只调节表达，不修改设置，也不改变朗读正文。宿主仅接受最多 300 字的指导，不接受模型指定 Key、服务地址、音色 ID 或替换朗读文字。

语音调用中，固定要求与本条指导合成独立的 `user` 消息，正文放在 `assistant` 消息中。指令不会出现在 QQ 文字回复或长期对话正文里，也不会被加入朗读正文。小米实际演绎效果仍以试听为准。

直接 `/语音 原文` 时，开启自动表达会使用当前对话模型做一次受限的语气规划；规划仅查看当前账号、人格和会话的最近四条消息，原文保持不变。规划失败时提示并按固定设置朗读。工具 Agent 的最终回答需要语音时也可单独规划表达。

可用 `/语音 [温柔、慢一点，句末轻停顿] 没关系，我在。` 手动安排本条表达，此时不再调用自动规划。试听区也可填「本次表达指令」进行比较。关闭自动表达后，仍可使用固定要求和手动指令。

### 文字设计音色

「音色方式」可选择预置音色，或 `mimo-v2.5-tts-voicedesign` 文字设计音色。后者需填写音色描述，例如“青年男性，声音温润，略带气声，吐字清晰，节奏从容”；描述单独传给模型，此模式的 `audio` 只发送 `format`，不发送预置 `voice` ID。

音色描述适合写声音身份与质感，固定要求适合写长期表达偏好，本条指导负责当前句子的情绪和节奏。文字设计每次生成存在随机性，若要更稳定的声音身份，可选预置音色。两个模式切换时保留各自已填设置。

发送方式是 **OneBot `record`，即 QQ 原生语音条**。WAV 以 Base64 交给 NapCat，由 NapCat 转为 QQ 支持的语音；不会作为音频附件发送。语音与其他内容分开发送。媒体发送允许最多 60 秒的 QQ 回执时间。

每条默认最多 500 字，可设 20–1000 字；每个会话的不同回复至少间隔 5 秒，同一轮最多四条语音共用一个名额，最多同时处理两轮合成。超限会提示，绝不默默截断朗读原文。模型回复语音合成失败时保留文字并提示原因；QQ 发送失败时明确提示，不记录成已成功发送。

## 验证范围

`node --test test/outgoing-media.test.mjs` 覆盖持久化、格式/大小检查、会话隔离、QQ 收藏、Token Plan 与普通 API 请求格式、原生 `record`、失效和降级，以及经过真实本机 HTTP 的鉴权上传和密钥管理。

`node scripts/check-extension-ui.mjs` 使用隔离服务与无界面 Edge 验证上传、预览、删除、密钥输入、语音试听和窄屏明暗主题。测试不调用真实小米服务、不发送真实 QQ 消息。

上线后仍需以实际 Key 验证合成权限、音色效果，以及实际 QQ 语音转换、发送和手机播放。

接口参考：[NapCat 消息段](https://napneko.github.io/onebot/segment)、[小米官方 TTS 示例](https://github.com/XiaomiMiMo/MiMo-Skills/blob/main/skills/mimo-v2-5-tts/scripts/mimo_tts.py)。
