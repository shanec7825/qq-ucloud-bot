# 图片、表情包与 QQ 原生语音

NapCat「机器人」扩展工作台新增 **图片与表情包** 和 **语音** 两页。群聊仍需在允许回复的群内 @ 机器人；静默监测群保持静默。

## 一次回复发送多条消息

模型可按交流节奏输出 1–8 条消息，日常聊天优先 2–4 条、一个意思一条，短回应可只发一条。每条包含文字和可选的图片、表情包或语音，正文最多 1500 字，整轮最多两张素材；不为凑数拆分代码块和连贯段落。模型一次生成完整分条计划，宿主校验后顺序发送；短口语未分组时有本地句末拆分兜底。

每条文字之后发送该条的图片和原生语音，再进入下一条。首条立即发送，后续气泡间隔约 0.4–1.2 秒；语音已经带来等待时不再额外延迟。群内只在首个成功发送的消息添加引用和 @。当前会话的整轮消息发完后才处理下一条请求，其他会话可继续各自处理。

发送失败或权限变化时停止后续投递，不自动重放可能已经发出的消息；记忆保留已投递内容与未完成状态。语音按每条独立语音内容和表达指导分别合成，共用一次频控名额；自动选择每轮最多一条。语音生成失败保留对应文字，并把不同的语音内容作为文字补上，不反复请求失败服务。

### 文字和语音可以说不同的话

开启「按语境决定语音」后，模型在同一次请求中判断是否需要语音，普通事实、代码、链接和详细步骤优先文字，安慰、问候、情绪表达可选用短语音。可以整轮不发语音；自动语音最多一条、最多 180 字，并受配置字数上限约束。明确要求“用语音回答”会优先满足，说“只发文字”“别发语音”会本轮禁止语音。例如文字发“地址发你了，三号门见”，语音说“路上慢一点，我等你”，两者互相补充。

模型计划中的 `text` 用于发文字，`speech.text` 用于合成语音；语音字数受「每条语音最多字数」限制。`speech.text` 为空表示该条只发文字或图片；文字为空、语音非空时可以只发语音。自动模式省略 `speech.text` 时不朗读文字；明确要求语音时旧格式仍可朗读文字。未开启自动语音、也未请求语音时，模型不能自行发送语音。

文字与语音是两条 QQ 消息，按顺序发出。只有实际投递成功的语音内容才作为已说的话写入会话记忆；表达指导不会写入正文。直接 `/语音 原文` 和 `/朗读 原文` 仍严格朗读原文。

## 图片与表情包

- 动漫图库收录 20 套、374 个表情，支持作品、角色和情绪筛选、每批 24 个、批量启用和停止后续下载。来源与完整说明见 [自然聊天与动漫素材](CHAT-DELIVERY-20261023.md)。
- 页面上传 PNG、JPEG、GIF、WebP，单个最大 8MB，最多 1000 个、总计 200MB。原文件保存到 `data/outgoing-media/`，GIF 保留原始字节。
- 上传时选择 QQ 账号、图片/表情包和使用范围：指定群、指定私聊或整个账号。整个账号的素材会在该账号的各会话中提供给机器人选择，请按实际共享意图设置。
- 在 QQ 附图或引用当前会话图片后发送 `/收藏图片 名称`、`/收藏表情包 名称`。普通用户也可收藏，但只保存到当前会话。引用其他会话的消息会被拒绝。
- `/图片`、`/表情包` 查看当前可用素材，`/图片 名称`、`/表情包 名称` 发送。支持列表编号或完整素材 ID；重名时使用编号或 ID。
- 模型每轮会获得当前会话中至多 40 项相关素材的名称、ID 和情绪标签，可以按话题选择最多两项配图。宿主校验 ID 和会话权限后发送。模型不能指定本机文件路径或任意 URL。
- 页面可预览、删除；收藏内容在重启后保留。素材按账号与会话隔离；同一会话更换人格不会清除其素材。

## 小米 MiMo 语音

1. 「语音」页默认使用 Token Plan 中国地址 `https://token-plan-cn.xiaomimimo.com/v1`，Key 使用 `tp-`/`ttp-`。也可选择按量 API `https://api.xiaomimimo.com/v1` 和 `sk-` Key。回答模型和 TTS 可共用保存的 MiMo Key。
2. 开启语音、选择音色和语气，保存后生成试听。Key 加密保存在现有密钥库中，页面留空保留。
3. 发送 `/语音 你好` 或 `/朗读 Hello` 朗读原文；发送 `用语音回答：你的问题` 合成模型回复。可开启「按语境决定语音」，让模型为适合听的聊天回复选择语音。

Token Plan 的使用场景与配额规则以[小米官方说明](https://mimo.mi.com/docs/zh-CN/tokenplan)为准。当前接入支持中国集群，并会按 `tp-`/`ttp-` Key 使用对应地址。

默认模型为 `mimo-v2.5-tts`，默认中文音色「冰糖」，另有茉莉、苏打、白桦和 Mia、Chloe、Milo、Dean 等音色。接口为所选根地址的 `/chat/completions`，请求非流式 WAV。

### 每条回复的自动表达

默认开启「按内容自动调整表达」。当前回答模型（选择 MiMo 按量 API 或 Token Plan 时即 MiMo Agent）会在同一次对话请求中生成文字、语音内容和独立的 `speech.style` TTS 指令，根据实际语音内容、人格与已授权上下文安排语调、情绪、语速、停顿、重音、气息和音色质感。

固定预置音色或音色描述保持为设置中的值；表达指导只能在既定声音身份内微调音色质感，不更换音色。管理员的「固定语气与语速要求」优先。本条指导只调节表现，不修改设置，也不改写已经选定的 `speech.text`。宿主仅接受最多 300 字的指导，不接受模型指定 Key、服务地址或音色 ID。关闭自动表达也能分别生成文字和语音。

语音调用中，固定要求与本条指导合成独立的 `user` 消息，正文放在 `assistant` 消息中。指令不会出现在 QQ 文字回复或长期对话正文里，也不会被加入朗读正文。小米实际演绎效果仍以试听为准。

直接 `/语音 原文` 时，开启自动表达会使用当前对话模型做一次受限的语气规划；规划仅查看当前账号、人格和会话的最近四条消息，原文保持不变。规划失败时提示并按固定设置朗读。工具 Agent 的最终回答需要语音时也可单独规划表达。

可用 `/语音 [温柔、慢一点，句末轻停顿] 没关系，我在。` 手动安排本条表达，此时不再调用自动规划。试听区也可填「本次表达指令」进行比较。关闭自动表达后，仍可使用固定要求和手动指令。

### 文字设计音色

「音色方式」可选择预置音色，或 `mimo-v2.5-tts-voicedesign` 文字设计音色。后者需填写音色描述，例如“青年男性，声音温润，略带气声，吐字清晰，节奏从容”；描述单独传给模型，此模式的 `audio` 只发送 `format`，不发送预置 `voice` ID。

音色描述适合写声音身份与质感，固定要求适合写长期表达偏好，本条指导负责当前句子的情绪和节奏。文字设计每次生成存在随机性，若要更稳定的声音身份，可选预置音色。两个模式切换时保留各自已填设置。

发送方式是 **OneBot `record`，即 QQ 原生语音条**。WAV 以 Base64 交给 NapCat，由 NapCat 转为 QQ 支持的语音；不会作为音频附件发送。语音与其他内容分开发送。媒体发送允许最多 60 秒的 QQ 回执时间。

每条默认最多 500 字，可设 20–1000 字；自动语音另有每轮一条、180 字上限。每个会话的不同回复至少间隔 5 秒，同一轮共用一个名额，最多同时处理两个合成请求。超限会提示，绝不默默截断朗读原文。模型回复语音合成失败时保留文字并提示原因；QQ 发送失败时明确提示，不记录成已成功发送。

## 验证范围

`node --test test/outgoing-media.test.mjs` 覆盖持久化、格式/大小检查、会话隔离、QQ 收藏、MiMo 按量 API 与 Token Plan 请求格式和 Key/地址匹配、原生 `record`、失效和降级，以及经过真实本机 HTTP 的鉴权上传和密钥管理。

`node --test test/independent-speech.test.mjs` 覆盖文字与语音内容不同、混合投递、纯语音、失败转文字、长度与字段限制、旧格式兼容，以及关闭自动表达时的独立语音内容。

`node scripts/check-extension-ui.mjs` 使用隔离服务与无界面 Edge 验证上传、预览、删除、密钥输入、语音试听和窄屏明暗主题。测试不调用真实小米服务、不发送真实 QQ 消息。

上线后仍需以实际 Key 验证合成权限、音色效果，以及实际 QQ 语音转换、发送和手机播放。

接口参考：[NapCat 消息段](https://napneko.github.io/onebot/segment)、[小米官方 TTS 示例](https://github.com/XiaomiMiMo/MiMo-Skills/blob/main/skills/mimo-v2-5-tts/scripts/mimo_tts.py)。
