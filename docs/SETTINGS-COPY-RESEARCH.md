# 设置页文案调研与优化

日期：2026-10-21。范围：NapCat 扩展页及保留的原生配置弹窗。

## 参考与取舍

- [AstrBot WebUI](https://docs.astrbot.app/use/webui.html)：参考按 AI、平台与消息、访问控制等用途分区，以及搜索定位配置。这些用途分组保留在“设置分类”的下拉选项中，不额外创建侧栏。
- [GOV.UK 文本输入规范](https://design-system.service.gov.uk/components/text-input/)：标签应短而直接，说明和示例不靠占位符承载。因此保留可见标签，把生效范围、单位和示例放在关联的说明文字中。
- [GOV.UK 详情组件](https://design-system.service.gov.uk/components/details/)：仅把部分用户需要的补充说明折叠。页面用途和重要开关的影响仍直接可见。
- [Microsoft 操作说明规范](https://learn.microsoft.com/en-us/style-guide/procedures-instructions/writing-step-by-step-instructions)：标题描述用户能完成的事，保持平行表达，删除重复标题的介绍句。

以上用于信息组织与文案，未复制第三方界面或代码。命名最终以本项目实际行为为准。

## 关键更名

| 原名称 | 新名称 | 用户能判断的用途 |
| --- | --- | --- |
| 基本设置 | 机器人身份 | 名字、默认风格、管理员 |
| 群组规则 | 群聊回复 | 哪些群可以回复、怎样回答 |
| 人格池 | 角色与语气 | 创建名字与回答风格 |
| 群聊 / 私聊人格 | 会话角色分配 | 为某个群或好友指定角色 |
| 记忆管理 | 长期记忆 | 保存长期事实、偏好和要求 |
| 记忆设置 | 记忆与上下文 | 是否引用记忆、保留多少近期内容 |
| 即时提醒 | 群消息提醒 | 在线收到重要消息后私聊提醒 |
| 定时总结 | 群消息定时整理 | 定期回看历史消息、提取通知 |
| 群摘要 | 群聊背景摘要 | 为回答提供背景，不向群发送 |

## 文案规则

1. 开关直接写动作，例如“在这个群回复”“私聊发送整理结果”，避免孤立的“启用”。
2. 字段带上对象，例如“账号备注”“角色名称”“用于哪种聊天”，避免重复使用“名称”“类型”。
3. 时间、数量说明包含单位与范围，例如“1–120 秒”“2–40 条”。
4. 保存、删除和附加操作分别显示“保存更改”“删除所选内容”“保存并执行”。
5. 同一套文案由 `napcat-plugin/webui/copy.mjs` 提供给扩展页和原生弹窗；配置键、存储格式和行为不变。

## 核对过的行为边界

- 群回复规则供各 QQ 使用，普通群须被 @ 才回复。定时整理群始终静默，暂停整理也不解除。
- 实时提醒只处理在线收到的消息；定时整理依赖本机聊天记录导出服务。
- 历史背景用于回答时，当前仅适用于默认 QQ 的基础角色；还需总开关、对应群的历史开关及记忆开关。
- 关闭“回答时使用记忆”会停止引用长期记忆和近期上下文，并非仅关闭聊天记录保存。
- 新建 QQ 连接不会自动登录新的 QQ。

## 验证

扩展页隔离验证覆盖五个模块、独立账号密钥、角色分配、群聊回复设置保存、导航搜索、未保存保护、恶意文本安全显示及手机深色布局。原生界面继续验证八次保存及账号、角色、记忆、提醒的操作路径。测试不连接真实 QQ 或外部模型。

最终外观参照 NapCat 本身：移除先前自定义工作台，使用原生同款 HeroUI 控件与外层主题。最终截图：`data/napcat-extension-native-light.png`、`data/napcat-extension-native-mobile-dark.png`。
